# CONNECTIONS.md - Registro Vivo de Conexiones

## Conexiones Activas (TP 1 — Núcleo de Datos y APIs CRUD, TP 2 — Autenticación y Seguridad, TP 3 — IA y Tiempo Real)

| Origen | Destino | Protocolo / Transporte | Propósito | Manejo de Fallo / Tolerancia |
|---|---|---|---|---|
| `backend-django` | PostgreSQL (5432) | TCP / psycopg3 | Persistencia transaccional ACID: Proveedores, Insumos, Compras, Productos, Recetas, Ventas, Turnos, Usuarios y Perfiles. | Transacciones atómicas (`@transaction.atomic`); fallback de desarrollo/test a SQLite si se configura `USE_SQLITE=True`. |
| `backend-node` | MongoDB (27017) | Mongoose / Mongo Wire | Persistencia documental: colecciones `historial_precios`, `snapshots_costeo` e `importaciones_ia` (entrada, salida, latencia, versión de prompt y estado). | Reconexión automática de Mongoose; los errores 500 se capturan en `error.middleware.js`. |
| `backend-node` (`django.client.js`) | `backend-django` (`/api/productos/:id/`) | HTTP / JSON | Consulta de catálogo y costo actual de producto para generar resumen consolidado. | Timeout de 3000ms con `AbortSignal.timeout(3000)`. Fallback elegante con objeto `{ degradado: true }` sin tirar la API de Node. |
| `backend-django` (Emisor SimpleJWT RS256) | Clientes HTTP / `backend-node` | Criptografía asimétrica (JWT RS256) | Emisión central de access tokens (15m) y refresh tokens (24h) con claims de rol y permisos granulares (ADR-0001). | Verificación autónoma offline en Node con clave pública sin pegarle a PostgreSQL. Expiración breve de 15 min y bloqueo inmediato al refrescar. |
| Clientes HTTP / PWA | `backend-node` (`verificarToken` / `verificarPermiso`) | HTTP Bearer Header / RS256 | Autenticación y autorización granular en memoria local sobre endpoints protegidos (`/api/productos/:id/resumen-costo`, `/api/historial-precios`, `/api/snapshots-costeo`, `/api/importaciones`). | Respuestas de error unificadas (401 Unauthorized / 403 Forbidden) según `docs/api-errores.md`; validación offline con clave pública RSA sin depender de conexión con Django. |
| Clientes HTTP / PWA | `backend-django` / `backend-node` (Perímetro Endurecido T2.5) | HTTP / CORS / Rate Limiter / Helmet / Sanitizer | Protección perimetral de transporte: CORS restringido a orígenes autorizados (sin comodín `*`), Rate Limiting (contra fuerza bruta y endpoints costosos), cabeceras de seguridad Helmet, prevención de inyecciones NoSQL y sanitización de credenciales en logs. | Rechazo con respuestas estandarizadas 403 Forbidden (CORS no autorizado), 429 Too Many Requests (Rate limit excedido) y 400 Bad Request (inyección NoSQL detectada) según `docs/api-errores.md`. |
| Clientes HTTP / PWA | `backend-django` (Autorización Granular y Objeto T2.6) | HTTP Bearer Header / RS256 | Control de acceso exhaustivo por permiso granular sobre todos los endpoints de negocio (Insumos, Compras, Recetas, Costos, Ventas, Caja, Personal y Auditoría) con reglas de objeto y arqueo ciego. | Rechazo sistemático con HTTP 403 Forbidden y formato { mensaje, detalles: null } según `docs/api-errores.md`; enmascaramiento estricto de costos y saldo esperado sin privilegios. |
| `backend-node` (`ai.client.js` T3.2) | `ai-service` (`POST /v1/extraer-precios`, `POST /v1/resumen-semanal`, `/health`) | HTTP / JSON (FastAPI 8001) | Orquestación asíncrona de extracción de listas de precios (HU7): Node recibe `POST /api/importaciones` (responde 202), invoca a `ai-service` en segundo plano, valida la salida y persiste trazabilidad en `importaciones_ia`. | Timeout de 12000ms con `AbortSignal.timeout(12000)`, validación estricta de ítems en `validarYNormalizarSalidaIA` y degradación automática a estado `CONTINGENCIA` en MongoDB sin bloquear el servidor. |
| `ai-service` (`ProveedorIA` Adapter T3.1) | Proveedor de IA (`GeminiAdapter` HTTPS / `OllamaAdapter` HTTP 11434) | HTTPS (`x-goog-api-key`) / HTTP JSON | Inferencia desacoplada mediante patrón Adapter (ADR-0002) con prompts versionados (`prompts/v1/`) y separación estricta entre instrucciones del sistema y datos del usuario. | Timeout configurable (`AI_TIMEOUT_SECONDS=10.0`), reintentos acotados (`AI_MAX_RETRIES=2`) y degradación automática a respuesta de contingencia sin bloquear el sistema. |
